# 框架规范 —— 审计数据 → 可插拔 3D 表现

> 设计原则（回应"不要定死"）：**数据与表现完全分离**。一份审计 JSON 可以接任意多种
> 3D 表现框架；每个框架只负责"把同一份数据讲成一种可读的故事"。表现不是定死的——
> 城市读总览，星野读规模，解剖读结构，按需要切换。

## 数据 schema v1（所有框架共用）

```jsonc
{
  "meta": { "package": "com.google.android.youtube", "version": "20.44.36(1557784000)",
            "note": "官方 universal vs 修改版 split 集, 逐文件 CRC 比对" },
  "files": [ { "p": "res/drawable-xxhdpi/…", "s": 12345, "st": "same" },
             { "p": "classes5.dex", "s": 7880572, "st": "mod" },
             { "p": "lib/armeabi-v7a/libvpx.so", "s": 580936, "st": "del" } ]
}
```

- `st` 状态机：`same`(与官方逐字节一致) / `mod`(内容被修改) / `del`(仅官方有,被删除或被裁剪) / `add`(仅修改版有)
- 生成方式：`modaudit.py --official 官方包` 的文件级 diff 即此格式；或直接由
  v1 摘要校验结果导出
- 可扩展字段（预留）：`layers`（分层手法）、`discoveries`（扫描玩法目标）、`methods`（方法级 diff 摘要）

## 已建框架

### F1 「APK 之城」— apk_city_template.html（可读性优先，推荐默认）

城市隐喻：文件=楼（楼高=文件大小），目录=城区（浮空路牌），被改=红楼呼吸辉光，
被裁剪=整片线框幽灵城区。**打开第一眼就能看见"哪几片城区被平了"**。
- 技术要点：InstancedMesh 单次绘制承载上万建筑；城区按路径前两级程序化布局；
  浮空路牌为 canvas 贴图 Sprite
- 实例：`apk_city_youtube.html`（YouTube 20.44.36，data/yt_files.json 内联）

### F2 「文件星野」— file_galaxy_template.html（规模沉浸模式）

星野隐喻：文件=星，亮度=大小，状态=颜色。可读性弱于城市，但更适合"感受修改的
稀疏与克制"——万星之中只有几点异色。与城市视图共用同一份 JSON，作为切换视图保留。

### F3 「分层解剖」— 规划中（数据驱动版 8 层结构 + 29 万方法实例化网格）

8 层手法剖面 + 方法层"零改动网格"（292815 个实例化小格全部同色的直观证据）。
数据接口：在 schema v1 上增加 `layers` / `methods` 字段（modaudit --deep 的输出）。

## 换包流程（每个新 App 都是三步）

```
1. python modaudit.py 新包.apk --official 同构建官方包   → 生成审计与 data JSON
2. 把 JSON 喂给任一框架模板（内联替换 __DATA__ 占位符）
3. 面板"研究文件"区点开对应 HTML
```

## 待解决问题
